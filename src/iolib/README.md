# src/iolib

Слой ввода-вывода. Здесь живёт всё, что связано с загрузкой портфелей с диска, выгрузкой результатов расчёта и сборкой человекочитаемых риск-отчётов. Прайсеры и риск-модели не зависят от форматов файлов: они получают уже разобранный объект портфеля и возвращают DataFrame'ы, которые этот слой сохраняет или собирает в отчёт.

## Место в проекте

UI-страницы (`src/ui/var_page.py`, `lvar_page.py`, `portfolio_var_page.py`) используют `iolib` в двух точках. На входе `PortfolioImporter` читает загруженный пользователем файл и отдаёт список dataclass-инструментов из `src/instruments/`. На выходе `ReportBuilder` собирает форматированный отчёт по результатам VaR/LVaR/CVaR, а `ResultsExporter` сохраняет «сырые» таблицы для скачивания.

Все форматные различия (YAML, JSON, CSV, Excel) скрыты в подпакете `serializers/`. Сам `iolib` оперирует словарями и DataFrame'ами и выбирает сериализатор по расширению файла.

## portfolio_io.py

Двусторонний мост между файлом портфеля и объектами `InterestRateSwap`, `CurrencyForwardContract`, `CurrencySwapContract`. Поддерживаемые типы перечислены в `_INSTRUMENT_TYPES = {"FXForward", "FXSwap", "IRS"}`. Файлы под XCCY и Cap/Floor существуют в `src/instruments/`, но в этом множестве их нет: загрузчик такие записи отвергнет.

Класс `PortfolioExporter(serializer: BaseSerializer)` принимает уже готовый объект сериализатора (выбор формата делается на уровне вызывающего кода через `serializers.SERIALIZERS` или `EXT_TO_SERIALIZER`). Метод `save(portfolio: list[BaseInstrument]) -> bytes` превращает каждый инструмент в словарь через внутренний хелпер `_instrument_to_dict`, отдаёт сериализатору и возвращает байты. Запись на диск выполняет вызывающий код.

Класс `PortfolioImporter(serializer: BaseSerializer)` решает обратную задачу: метод `load(raw: bytes) -> tuple[list[BaseInstrument], list[str]]` принимает сырые байты файла, прогоняет их через сериализатор, собирает датаклассы инструментов через `_dict_to_instrument` и возвращает кортеж `(инструменты, список ошибок парсинга по записям)`. Сериализатор фиксируется в конструкторе, никакого автоопределения по расширению внутри `load` нет — выбор сериализатора по расширению делает вызывающий код через `EXT_TO_SERIALIZER`. Парсинг полей идёт через приватные хелперы `_parse_bool`, `_parse_float_or_none`, `_parse_date`, что обеспечивает мягкую обработку как «строгих» (JSON/YAML) форматов, так и «плоских» (CSV/Excel), где всё приходит строками.

## report_builder.py

Класс `ReportBuilder` собирает структурированный отчёт по портфелю: добавляет именованные секции (`add_section`, `remove_section`, `has_section`, `sections_count`) и в методе `build()` рендерит итоговый документ. Внутри `_render_section` и `_render_dataframe` отвечают за форматирование DataFrame'ов в таблицы, а `_find_unicode_font` подбирает шрифт с поддержкой кириллицы для PDF-вывода (важно, потому что заголовки и комментарии у пользователя на русском).

Используется UI-страницами как «накопитель»: страница последовательно складывает в билдер блоки (исходный портфель, таблица VaR по инструментам, портфельный VaR, LVaR-разложение) и в конце получает готовый файл для скачивания.

## results_exporter.py

Класс `ResultsExporter(serializer)` отвечает за выгрузку «сырых» результатов расчёта (таблиц VaR, временных рядов NPV, разложения LVaR). Метод `export(data: dict) -> bytes` диспатчит на `_export_csv` или `_export_excel` по типу инстанса сериализатора (`isinstance(self._serializer, CsvSerializer/ExcelSerializer)`), а не по расширению пути; при этом `_to_serializable` приводит numpy/pandas-типы к примитивам, чтобы избежать проблем сериализации. Запись на диск выполняет вызывающий код.

В отличие от `ReportBuilder`, который собирает форматированный отчёт, `ResultsExporter` отдаёт данные «как есть»: их удобно дальше подгружать в Excel или другие инструменты анализа.

## Подпакет serializers/

Файлово-форматный слой. Сам по себе ничего не знает про портфели — оперирует только `bytes` и питоновскими структурами. Подробности в `serializers/README.md`.
