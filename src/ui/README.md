# src/ui

Папка содержит слой пользовательского интерфейса проекта `course_work_risk_calc`.
UI построен на Streamlit, а точкой входа является `src/main.py`, который собирает
многостраничную навигацию и подключает страницы из этой директории. Каждая
страница отвечает за отдельный сценарий работы пользователя: построение
портфеля, расчёт рисковых метрик одного инструмента, оценка
ликвидно-скорректированного риска и расчёт портфельного VaR.

## Состав страниц

В корне `src/ui/` располагаются страницы Streamlit. Сами страницы намеренно
тонкие: они отвечают за компоновку, чтение состояния сессии и вызов модулей
расчёта, а тяжёлые элементы интерфейса вынесены в подпапки `common/`,
`lvar_common/` и `portfolio_common/`.

| Файл | Назначение |
|---|---|
| `portfolio_page.py` | Работа с портфелем: загрузка из YAML, JSON, CSV, Excel через `iolib.portfolio_io`, добавление и редактирование инструментов, экспорт. Использует формы из `common.sidebar` для конструирования контрактов и виджеты `common.components`. |
| `var_page.py` | Расчёт VaR и Expected Shortfall для отдельного инструмента портфеля. Получает дневной ряд NPV через диспетчер прайсеров и считает метрики модулями `compute.risk.var` и `compute.risk.civar`. |
| `lvar_page.py` | Расчёт ликвидно-скорректированного VaR (LVaR) для инструментов портфеля. Параметры ввода, выбор модели ликвидности и отображение результатов вынесены в `lvar_common/`. |
| `portfolio_var_page.py` | Расчёт портфельного VaR с учётом корреляций между инструментами, разложение на диверсифицированный, недиверсифицированный и некоррелированный VaR, тепловая карта корреляций и анализ P&L портфеля. |

## Как страницы используют ядро расчётов

Поток данных одинаков для страниц риска. Сначала пользователь задаёт
горизонт, окно истории и доверительный уровень. Затем страница инициализирует
`utils.DataProvider.DataProvider` с каталогом данных `src/data/`. Через
диспетчер `compute.pricers.pricer_dispatch` каждый поддерживаемый инструмент
из портфеля переводится в дневной временной ряд NPV. Полученные ряды
передаются в risk-модули из `compute/risk/`: `var.py`, `civar.py`, `lvar.py`,
`portfolio_var.py`. Конкретный набор расчётов зависит от страницы.

Страница `var_page.py` работает с одним инструментом, поэтому она вычисляет
дневные приращения P&L, масштабирует их к горизонту и применяет историческую
percentile-оценку через `var.historical` либо параметрическую через
`var.parametric`/`var.parametric_es`. Cornish-Fisher здесь не используется;
Component VaR и Incremental VaR из `compute.risk.civar` подключены отдельно
на странице портфельного VaR. Страница `lvar_page.py`
дополнительно подключает модель ликвидности из `lvar_common.liquidity_model`,
наблюдаемые спреды, рассчитанные через `compute.modelling.liquidity`, и
комбинирует базовый VaR с ликвидной добавкой. Страница `portfolio_var_page.py`
строит матрицу P&L по инструментам, считает корреляции, агрегирует
портфельный VaR и раскладывает его на компоненты, а также показывает
распределение P&L портфеля с отметкой выбранного квантиля.

## Состояние сессии и детектор устаревания

Параметры, выбранные на одной странице, сохраняются в `st.session_state`,
чтобы страницы могли согласованно использовать единые значения даты оценки,
горизонта и доверительного уровня. Ключи `_pvar_params_key` и `_params_key`
используются не для кеширования результатов, а для отслеживания изменений
входных параметров: если ключ перестал соответствовать сохранённому
результату, страница показывает предупреждение «Параметры изменились».
Сами расчёты не кешируются: повторный клик по кнопке расчёта запускает
полный пересчёт.

## Зависимости

Страницы опираются на следующие пакеты проекта: `instruments/` для
типизированных контрактов, `compute/pricers/` для оценки NPV, `compute/risk/`
для VaR, CVaR и LVaR, `compute/modelling/` для кривых дисконтирования и
моделей ликвидности, `utils/DataProvider.py` для доступа к рыночным данным,
`iolib/portfolio_io.py` для загрузки и сохранения портфелей и
`iolib/results_exporter.py` для выгрузки результатов.
