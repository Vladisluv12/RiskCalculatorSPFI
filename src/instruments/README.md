# src/instruments

## Назначение пакета

Пакет `instruments` хранит описания финансовых контрактов, с которыми работает калькулятор риска. Здесь нет вычислительной логики: каждый файл объявляет датакласс, фиксирующий условия сделки (номинал, валюту, ставки, даты, конвенции), либо перечисление допустимых значений для полей этих датаклассов. Эти типы являются «языком», на котором остальной проект общается между слоями: загрузчики портфелей (`iolib/portfolio_io.py`) собирают объекты из YAML/JSON/CSV/Excel, прайсеры (`compute/pricers/`) принимают готовые контракты и строят временные ряды NPV, а Streamlit-страницы в `src/ui/` используют те же датаклассы и enum'ы для построения форм ввода и валидации.

## Базовый класс

Файл `BaseInstrument.py` содержит общий датакласс `BaseInstrument`, от которого наследуются все конкретные инструменты. Он фиксирует минимальный набор атрибутов любого контракта.

| Поле | Тип | Смысл |
|---|---|---|
| `instrument_id` | `str` | Идентификатор сделки в портфеле |
| `notional` | `float` | Номинал |
| `direction` | `Direction` | Сторона сделки (покупка или продажа) |
| `start_date` | `datetime` | Дата начала действия |
| `end_date` | `datetime` | Дата окончания |

Базовый класс принципиально не знает ни про валюты, ни про ставки. Всё, что зависит от типа инструмента, добавляется в наследниках.

## Конкретные инструменты

### `IRSwap.py`, класс `InterestRateSwap`

Процентный своп (IRS либо OIS-своп). Наследует `BaseInstrument` и добавляет `currency` и параметры двух ног. Фиксированная нога описывается ставкой `fixed_rate` (в долях единицы), конвенцией дней `fixed_day_count`, частотой выплат `fixed_payment_timing` и правилом смещения `fixed_offset_rule`. Плавающая нога задаётся индексом `floating_index` (значение из `FloatingIndex`), спредом `floating_spread` в базисных пунктах и собственными параметрами `floating_day_count`, `floating_payment_timing`, `floating_offset_rule`. Этот датакласс является основным входом в `IRSPricer`, который смотрит на `floating_index.is_ois_based`, чтобы выбрать ветку расчёта (par-float для OIS-индексов или flat-fixing для IBOR).

### `FXForward.py`, класс `CurrencyForwardContract`

Валютный форвард. К базовым полям добавляются `currency_pair` (значение `CurrencyPair`), строковые `base_currency` и `quote_currency`, согласованный `forward_rate`, опциональный `spot_rate` и флаг `is_ndf` для расчётных (non-deliverable) контрактов. У поля `quote_currency` двойной смысл: при `is_ndf=True` это валюта расчёта, при поставочном форварде это вторая валюта пары. Используется `ForwardPricer`, который через `DataProvider.get_currency_data` подтягивает спот-серию и дисконтирует обе валютные стороны по соответствующим OIS-кривым.

### `FXSwap.py`, класс `CurrencySwapContract`

Валютный своп с двумя обменами (near leg и far leg). Помимо валютной пары и базовой/расчётной валют контракт хранит `fixed_sum` в `fixed_sum_currency`, зафиксированный спот `spot_rate`, своп-пункты `swap_points` (один пункт равен 0.0001) и опциональный явно заданный курс обратного обмена `reverse_rate`. Поля `initial_payment_*` и `final_payment_*` объявлены как `Optional[...] = None` и хранят, при необходимости, суммы платежей в обеих валютах для near и far ноги. Свойство `forward_rate` возвращает `reverse_rate`, если он задан, иначе `spot_rate + swap_points * 0.0001`. Прайсер контракта называется `CurrencySwapPricer`.

### `XCCY.py`, кросс-валютный своп

Файл зарезервирован под датакласс кросс-валютного свопа (XCCY). На текущий момент модуль пуст: контракт ещё не реализован, и в `pricer_dispatch.py` для него пока нет ветки. Файл оставлен как заглушка для будущей разработки.

### `CapFloor.py`, опционы Cap/Floor

Аналогично, заготовка под Cap/Floor (опционы на процентную ставку). Реализация и соответствующий прайсер планируются позднее.

## Перечисления (`enums.py`)

Файл собирает все enum'ы, разделяемые между датаклассами, прайсерами и UI. Они служат единым источником допустимых значений и предотвращают «магические строки» в портфелях.

### `Direction`
Сторона сделки. Значения `BUY` и `SELL`. Используется в `BaseInstrument.direction` и применяется прайсерами для смены знака денежных потоков.

### `Currency`
Валюты, поддержанные расчётной частью: `USD`, `RUB`, `EUR`, `CNY`. Используется в `InterestRateSwap.currency` и косвенно через привязку индексов и кривых.

### `CurrencyPair`
Валютные пары для FX-инструментов: `USD/RUB`, `EUR/RUB`, `EUR/USD`, `CNY/RUB`. Поле в `CurrencyForwardContract` и `CurrencySwapContract`.

### `DayCountConvention`
Конвенции расчёта долей года: `_30E_360`, `ACT_360`, `ACT_365`, `ACT_ACT` (ISDA). Передаётся в обе ноги IRS и используется функцией `year_fraction` из `compute/pricers/swap_utils.py`.

### `PaymentTiming`
Частота купонных выплат: `MONTHLY`, `QUARTERLY`, `SEMI_ANNUALLY`, `ANNUALLY`, `END_OF_PERIOD`. Используется при построении расписания платежей через `generate_payment_schedule`.

### `OffsetRule`
Правило смещения дат выплат относительно конца периода: `NONE`, `ONE_DAY`, `TWO_DAYS`. Соответствует приложению к договору и применяется при построении расписания.

### `FloatingIndex`
Самый «умный» enum пакета. Перечисляет плавающие индексы для процентных свопов (`RUONIA_AVG`, `RUONIA_COMP`, `ESTR_COMP`, `SOFR_COMP`, `EURIBOR_EUR_1M/3M/6M`, `RUSFAR_RUB_3M`, `RUSFAR_RUB_ON`, `RUSFARCNY_COMP`, `RUB_KEY_RATE`) и предоставляет три свойства, на которые опирается `IRSPricer`.

| Свойство | Возвращает | Используется для |
|---|---|---|
| `is_ois_based` | `bool` | Выбор ветки расчёта плавающей ноги: `True` означает форвард, выводимый из OIS-кривой через тождество par-float, `False` — flat-fixing IBOR с поправкой на базис |
| `currency` | ISO-код валюты | Подбор соответствующей OIS-кривой и фиксингов в `DataProvider` |
| `ibor_ois_tenor_years` | срок в годах | Длина OIS-сегмента, к которому привязывается базис «фиксинг минус OIS». Свойство применимо только к не-OIS (IBOR) индексам; для OIS-индексов выбрасывает `ValueError` |

Свойство `is_ois_based` задаёт классификацию: индексы, по которым строится OIS-дисконтирование напрямую (`RUONIA_*`, `ESTR_COMP`, `SOFR_COMP`, `RUSFARCNY_COMP`), против IBOR-индексов, для которых форвард выводится из OIS-кривой соответствующего срока с поправкой на исторический rolling-mean базис.

## Как пакет вписывается в общий поток данных

Загрузчик портфеля собирает объекты `InterestRateSwap`, `CurrencyForwardContract` или `CurrencySwapContract` из пользовательского файла, подставляя значения enum'ов по их строковым представлениям. Полученные контракты передаются в `pricer_dispatch.py`, который по типу инструмента вызывает нужный прайсер. Прайсеры читают только публичные поля датаклассов и возвращают временной ряд NPV. Дальше серия попадает в модули из `compute/risk/`, где считаются VaR, CVaR и LVaR. UI-страницы (`var_page.py`, `lvar_page.py`, `portfolio_var_page.py`) формируют формы ввода и валидируют значения через эти же enum'ы, что гарантирует консистентность между слоями.
