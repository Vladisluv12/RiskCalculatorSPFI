# compute/risk

Пакет содержит реализации риск-метрик портфеля деривативов. Все функции работают поверх временных рядов NPV, построенных прайсерами из `compute/pricers/`. Типичный сценарий: UI собирает портфель, через `pricer_dispatch.get_pv_series` получает по серии NPV на каждый инструмент, передаёт их в функции из этого пакета и отображает результат на страницах `src/ui/var_page.py`, `lvar_page.py`, `portfolio_var_page.py`.

## Общие соглашения

Публичные функции принимают `(dataProvider, instrument, calc_start, calc_end, ...)` и сами получают NPV-серию через `pricer_dispatch.get_pv_series`. Серия P&L внутри получается через `to_pnl` как разность последовательных NPV. Уровень доверия задаётся как `confidence_level` в долях (например, 0.99). Отдельного параметра `holding_period` в публичных функциях нет: горизонт берётся из `(calc_end − calc_start)` в днях, и параметрические оценки масштабируются множителем `sqrt(horizon_days)`.

## var.py — VaR одного инструмента

Модуль реализует исторический и параметрический VaR, а также соответствующие меры Expected Shortfall.

| Функция | Назначение |
|---|---|
| `to_pnl` | Преобразование серии NPV в серию P&L. |
| `historical` | Исторический VaR как отрицательный перцентиль распределения P&L, уже масштабированного на `sqrt(horizon_days)`. |
| `parametric` | Параметрический VaR в нормальном предположении с тем же масштабированием на горизонт. |
| `historical_es` | Историческая ES как среднее P&L в хвосте за порогом VaR. |
| `parametric_es` | Параметрическая ES в нормальном предположении. |

Внутренние помощники `_get_pv_series`, `_get_pnl_series`, `_resolve_target_column` приводят разные форматы входа к общему виду.

## civar.py — Component VaR и Incremental VaR

Несмотря на имя файла, модуль не реализует Cornish-Fisher CVaR. Здесь живут две классические декомпозиции портфельного VaR на вклады инструментов.

`compute_cvar` считает Component VaR: для каждого инструмента `CVaR_i = ρ(pnl_i, pnl_portfolio) · VaR_i`, где `ρ` — корреляция P&L инструмента с портфельным P&L. Скошенность и эксцесс не используются.

`portfolio_ivar` считает Incremental VaR: для каждого инструмента `IVaR_i = VaR_full − VaR_without_i` (полный портфельный VaR минус VaR портфеля с удалённым инструментом). Это вклад инструмента в общий риск через сценарий его исключения.

## lvar.py — Liquidity-adjusted VaR

`portfolio_lvar` считает VaR с поправкой на ликвидность: к классической оценке VaR добавляется компонент стоимости ликвидации (`Liquidity Cost`), вычисляемый по моделям из `compute/modelling/liquidity.py`. Для IRS-инструментов используется `compute_irs_lc` (через DV01 и спред в базисных пунктах), для остальных — `compute_lc` на базе EWMA-оценки волатильности bid-ask спреда. Результат позволяет учесть, что закрытие позиции в стрессовом сценарии само по себе несёт издержки, не отражённые в чистом распределении P&L.

## portfolio_var.py — агрегация по портфелю

Модуль агрегирует серии NPV нескольких инструментов в портфельный P&L и считает на нём расширенный набор оценок риска. Функции `portfolio_historical` и `portfolio_parametric` возвращают `dict` с шестью полями: `pnl_matrix` (матрица P&L по инструментам), `individual_vars` (вектор VaR по каждому инструменту), `corr_matrix` (корреляционная матрица), `diversified_var` (агрегированный VaR с учётом корреляций), `undiversified_var` (сумма индивидуальных VaR без учёта диверсификации) и `uncorrelated_var` (квадратный корень из суммы квадратов индивидуальных VaR, оценка без корреляций). Помимо них в модуле есть `portfolio_historical_es` и `portfolio_parametric_es` для портфельной Expected Shortfall.

Помощники `_deduplicate_columns`, `_get_pv_series`, `_get_pnl_series` приводят входные DataFrame к согласованному виду перед суммированием — имена колонок инструментов могут совпадать, и их нужно развести, чтобы корректно построить общий ряд P&L портфеля.
